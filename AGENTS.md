## System Overview

A 15-agent system for building a NiceGUI-based SAP GUI automation framework on Windows. The Orchestrator (Conductor) delegates discovery, design, implementation, and testing work to 14 specialist Performers. UI design is handled by ux-designer; implementation by 8 specialists scoped to layers/phases. Testing is orchestrated by testing-qa-engineer, which delegates to 3 test batch agents (unit, integration, performance) for isolated test execution. Plan agent leads pre-implementation discovery. All agents share persistent context via a 4-layer memory system in `.github/memory/`. The codebase bridges SAP's COM-based GUI scripting API to a NiceGUI frontend via a dedicated COM worker thread and asyncio queue.

## Test Batch Sub-Agent Architecture

The **testing-qa-engineer** is a test orchestrator that delegates actual test execution to three specialized batch agents:

| Agent | Responsibility | Command | Output |
|---|---|---|---|
| test-batch-unit | Unit tests (fast, mocked dependencies) | `pytest tests/unit/ --cov=sap --cov=config --cov=ui --tb=short -v` | Unit Test Results Report with coverage per-module |
| test-batch-integration | Integration tests (adjacent module interactions) | `pytest tests/integration/ --tb=short -v` | Integration Test Results Report with skip reasons |
| test-batch-performance | Performance benchmarks (regression detection) | `pytest tests/test_performance.py -v` | Performance Test Results Report with timing baselines |

**Orchestration flow**:
1. `testing-qa-engineer` receives delegation "Run assessment"
2. `testing-qa-engineer` delegates to all three batch agents in parallel
3. Each batch agent runs its test suite in isolation, captures output, parses results
4. Each batch agent returns a structured results report
5. `testing-qa-engineer` synthesizes all three reports into a unified **Unified Assessment Report** with phase gate decision
6. System Orchestrator receives unified report for phase gate decision

**Rationale**: Isolated batch execution eliminates timing race conditions, makes output capture deterministic, enables parallel test runs, and provides clear attribution of results to each batch.
